# Словарь терминов

Короткие определения слов, которые встречаются в руководстве и в кабинете. Термины сгруппированы по темам; подробности — по ссылкам.

## Люди и роли

| Термин | Что означает |
| --- | --- |
| Тимлид | Участник, координирующий работу команды. См. [команда](../common-info/team.md) |
| Ментор | Член жюри, закреплённый за командой на год. Консультирует, но не пишет код, не решает за команду и не оценивает её |
| Жюри | Те, кто проверяет проекты, задаёт вопросы на защитах и выставляет оценки по критериям |
| Проверяющие | Члены жюри, которым назначен ваш проект на текущий сезон. Видны в разделе «Моя команда» после публикации распределения |
| Организатор ПД | Отвечает за сроки, расписание, состав команд, штрафы и публикацию результатов. К нему идут организационные вопросы |
| Руководитель ПД | Отвечает за все процессы, а также ведомости и выставление баллов в БРС |

## Этапы и материалы

| Термин | Что означает |
| --- | --- |
| Сезон | Один учебный год ПД |
| Этап | Контрольная точка года: защита идеи, нулевая версия, предзащита или итоговая защита. См. [этапы](../common-info/stages.md) |
| Аннотация | Краткое описание идеи проекта, которое команда заполняет в кабинете до защиты идеи. См. [идея и аннотация](../stages/annotation.md) |
| Прототип | Ранняя работающая версия, на которой можно проверить задумку |
| Заглушка | Временная замена неготовой части: например, данные, записанные прямо в код, вместо ответа сервера |
| Сессия | Одна из встреч, на которых выступают команды. У этапа обычно несколько сессий |
| Дедлайн билда | Последний срок публикации версии для проверки. Наступает раньше дня защиты |
| Дедлайн презентации | Отдельный срок отправки презентации |
| Матрица ответственности | Таблица «задача — кто отвечает» |
| Диаграмма Ганта | План работ на временной шкале: что, когда и в какой последовательности |
| Номинация | Отдельная награда в виде бонусных баллов по итогам года; за номинации команда может получить до 10 бонусных баллов |

## Git и GitHub

| Термин | Что означает |
| --- | --- |
| Репозиторий | Хранилище кода, материалов и истории изменений проекта. См. [репозиторий и README](../submission/repository.md) |
| Коммит | Одно сохранённое изменение в истории Git с автором, датой и сообщением |
| Ветка | Параллельная линия разработки. Ветка по умолчанию обычно называется `main` или `master`; статистика считается по ней |
| Pull request | Предложение влить изменения из одной ветки в другую с возможностью обсудить и проверить их |
| Issue | Карточка задачи, ошибки или обсуждения в репозитории. Через issues жюри оставляет замечания |
| README | Файл `README.md` в корне репозитория: первое, что видит человек, открывший проект |
| Тег | Именованная метка на конкретном коммите, обычно с номером версии |
| Релиз | Страница выпуска на GitHub: тег, описание и файлы сборки либо ссылка на деплой. См. [сборка и релиз](../submission/release.md) |
| Contributors | Вкладка GitHub с графиком коммитов по участникам |

## Сборка и проверка

| Термин | Что означает |
| --- | --- |
| Билд, сборка | Версия программы, подготовленная к запуску: архив, установщик, APK |
| Деплой | Размещение работающей версии сервиса в интернете, а также сама размещённая версия |
| Подмена | Изменение сданного релиза или проверяемого деплоя после дедлайна. Запрещена |
| Стек | Технологии, из которых состоят части проекта: интерфейс, сервер, база данных. IDE и Git в стек не входят |
| Фреймворк | Готовый каркас приложения, в который команда добавляет свой код. Берёт на себя типовые задачи: маршруты, работу с базой данных, отрисовку интерфейса. См. [выбор технологий](stack-ideas.md) |
| Фронтенд, бэкенд | Части веб-приложения: интерфейс, который работает в браузере, и сервер, который обрабатывает запросы и хранит данные |
| Нативное приложение | Приложение, написанное инструментами самой платформы: например, на Kotlin для Android или Swift для iOS |
| Кроссплатформенное приложение | Приложение, которое собирается из одного кода под несколько платформ: например, на Flutter или Compose Multiplatform |
| API | Способ, которым одна программа обращается к другой за данными или действиями |
| Ассет | Готовый ресурс проекта: модель, иконка, звук, шрифт. См. [сторонние материалы](../submission/resources.md) |
| Лицензия | Условия, на которых автор разрешает использовать свой материал или код |

## Оценивание

| Термин | Что означает |
| --- | --- |
| Критерий | Отдельный пункт оценки с максимальным баллом. Критерии этапа видны в кабинете заранее |
| Штраф | Вычет за нарушение процедуры: просрочку, подмену, выход за регламент выступления. См. [оценивание](../results/grading.md) |
| Зачёт, дифференцированный зачёт | Форма отчётности: у первого курса — зачёт, у второго — зачёт с оценкой |
| БРС | Балльно-рейтинговая система университета, куда переносится итог ПД |

## ИИ и данные

| Термин | Что означает |
| --- | --- |
| Языковая модель | Программа, которая понимает и порождает текст; на языковых моделях работают чат-ассистенты. Доступна через API (YandexGPT, GigaChat) или локально (Ollama). См. [идеи проектов с ИИ](project-ideas.md) |
| Готовая модель | Обученная кем-то модель, которую команда встраивает в проект без обучения с нуля: распознавание речи, текста, поз, изображений |
| Дообучение | Настройка готовой модели на собственных данных под конкретную задачу |
| Эмбеддинг | Представление текста или изображения вектором чисел: близкие по смыслу объекты получают близкие векторы |
| Датасет | Набор данных для обучения или проверки модели, обычно с разметкой — правильными ответами |
| Распознавание речи | Превращение записи голоса в текст. Готовые модели: Whisper, Vosk |
| Распознавание текста, OCR | Чтение текста с изображения. Готовые инструменты: Tesseract, ML Kit |
| Метрика ИИ-части | Число, которое показывает качество работы модели: доля правильных ответов, процент побед бота, оценки участников тестирования |
