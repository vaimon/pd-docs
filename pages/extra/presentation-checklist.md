# Чек-лист презентации

Откройте готовый файл презентации и пройдите список. Для этапных пунктов проверяйте применимость: диаграмма Ганта нужна на нулевой версии и итоговой защите, а материалы о работающей версии — начиная с нулевой версии.

## На каждом этапе

- [ ] Есть титульный слайд с названием проекта.
- [ ] Есть слайд с составом команды и фотографиями.
- [ ] Понятно, что представляет собой проект и кто его пользователь.
- [ ] Сформулированы цель и задачи.
- [ ] Указан тип проекта: сайт, приложение, игра, чат-бот или другой вариант.
- [ ] Показаны референсы и источники.
- [ ] Технологии соотнесены с частями проекта; IDE, Git и графические редакторы не перечислены как стек приложения.
- [ ] Есть ссылка на открытый GitHub-репозиторий.

## На защите идеи

- [ ] Объяснено, почему выбрана эта идея.
- [ ] Представлена аннотация и ожидаемый результат.
- [ ] Есть содержательный анализ аудитории и аналогов.

## Начиная с нулевой версии

- [ ] Есть матрица распределения ответственности.
- [ ] Показаны конкретные результаты и изменения относительно предыдущей версии.
- [ ] Указано количество решённых issues.
- [ ] Описан личный вклад каждого: что сделано и в каком объёме.
- [ ] Добавлены графики коммитов.
- [ ] Скриншоты основных возможностей занимают не более пяти слайдов.
- [ ] Есть ссылка на публичную сборку или работающий сервис для проверки.
- [ ] Для нулевой версии и итоговой защиты есть диаграмма Ганта.

## Файл и читаемость

- [ ] Соотношение сторон — 4:3 или 16:9.
- [ ] Все слайды, кроме титульного, пронумерованы.
- [ ] На слайдах нет больших текстовых блоков.
- [ ] Текст и изображения контрастны; мелкие подписи читаются.
- [ ] Рекомендация по шрифтам учтена: без засечек, от 18 пунктов.
- [ ] Ссылки открываются, QR-коды сканируются.
- [ ] Сторонние материалы указаны в соответствии с требованиями.
- [ ] Подготовлен PDF либо PPTX, если нужна анимация.
- [ ] Получившийся файл просмотрен после экспорта, оформление не сместилось.

## Рассказ и сдача

- [ ] Рассказ отрепетирован и занимает от 4 до 6 минут.
- [ ] В начале кратко напоминается смысл проекта.
- [ ] Докладчик объясняет результаты, а не читает слайды целиком.
- [ ] Каждый участник готов объяснить свою часть.
- [ ] Проверен дедлайн презентации.
- [ ] Ссылка передана через форму нужного этапа и доступна проверяющим.
- [ ] Команда знает время и формат защиты.

Пояснения к пунктам: [презентация и выступление](../submission/presentation.md). Сборка сдаётся отдельно: [инструкция по релизу](../submission/release.md).
